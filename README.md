# nonfiction hotlist. 2025

The 2025 Nonfiction Hotlist as a website: a cover, a welcome, an about page, six pages of project cards, and a page for each of the 23 projects. Every page also exists in a downloadable PDF built from the same data.

**Live:** https://nfh2025.rdgnbl.com

## How it fits together

```
Google Drive kit         Where the text is edited (see below). The site reads from it.
content/
  content.json           All site text, mirrored from the Drive kit. **bold** marks the highlight.
  layout.json            Image paths and framing per project. Edited here, not in Drive.
  drive.json             The Drive kit's manifest ID, written when the kit is connected.
  sync-problems.txt      Drive edits that broke a rule and were skipped (empty when all is well).
src/page.html            The page: layout, styles and rendering. Its data block is generated.
site/                    What gets published. Everything here is served as-is.
  index.html             Built from src/page.html (npm run build). Don't edit by hand.
  img/                   Card art, banners and stills for each project.
  hotlist-2025.pdf       Built at publish time (npm run pdf). Not committed.
  og.jpg                 Link preview image (npm run og).
  CNAME, .nojekyll, 404.html, favicon.svg
drive-kit/
  setup.gs               Apps Script that builds the Drive kit (generated by npm run kit).
scripts/
  content/               spec.js (fields and limits), pull-drive.js (Drive to content.json),
                         write-page.js (content to src/page.html), build-kit.js, fake-drive.js
  build-site.js          Wraps src/page.html into site/index.html with metadata.
  build-pdf.js           Lays out the PDF (letter size) and prints it with Chromium.
  build-og.js            Renders the link preview image from the cover.
  check-site.js          Smoke test: every page, project and tab, on desktop and phone.
  images/                Crops and compresses images from the original asset folder.
```

There is no framework. `src/page.html` is one self-contained page that routes with the URL hash (`#welcome`, `#page-2`, `#vestibule`, `#vestibule.help`). The same file is also published as a Claude artifact, which is why it has no `<html>` or `<head>`; the build adds those for the website.

## Editing text: the Google Drive kit

The text is edited in Google Drive, in the `NFH 2025` folder:

```
00 How this works            Guide for editors
01 Cover, Welcome, About/    Google Docs, one heading per field. Bold becomes the highlight.
02 Index Pages/              Running order: a dropdown of project names per card slot.
03 Projects/<Title>/         A locked Google Sheet, <Title>_Copysheet (tabs: Page, Team, How to help, Links,
                             Laurels and awards, News) and a Media folder of images.
Site manifest (do not edit)  Maps every sheet and doc to the site. The workflow reads it.
```

Project sheets are locked except for the white cells, and each field has a character limit that the sheet enforces as people type. Docs can't be locked, so the reader checks them: a missing heading or an over-long passage is skipped, and that part of the site keeps its previous text.

**How edits reach the site.** The Publish workflow runs every 15 minutes. It reads the kit (`scripts/content/pull-drive.js`), and if anything changed it updates `content/content.json`, rebuilds the site and PDF, runs the smoke test, commits the text and publishes. Edits that break a rule are listed in `content/sync-problems.txt` and in the run summary; the run fails, which emails the repo owner, once each time that list changes. To publish right away, run the workflow from the Actions tab.

The kit is read through link sharing (anyone with the link can view), so no Google credentials are stored anywhere. Editing rights are whatever you grant in Drive.

**Building the kit.** `npm run kit` generates `drive-kit/setup.gs` from `scripts/content/spec.js`. Paste it into a new project at script.google.com and run `buildKit`. It fills the folder from `content/content.json` on GitHub, copies the images, sets link sharing and logs the Site manifest ID, which goes in `content/drive.json`. It pauses and resumes itself to stay under Google's time limit, and running it again only fills in what's missing.

**Changing fields or limits.** Edit `scripts/content/spec.js`, then `npm run test:kit` (checks the reader against a simulated export and a mock run of the setup script). Existing sheets keep their old layout until rebuilt.

**Working locally.** `npm run pull` reads the kit into `content/content.json` and the page. With no `content/drive.json`, it does nothing. Before changing code, pull first so you're working on the current text.

```sh
npm install              # first time only
npm run pull             # current text from Drive
npm run release          # build site/index.html, the PDF, run the smoke test
git commit -am "..." && git push
```

`npm run serve` previews the site at http://localhost:8080.

## Team dashboard

An unlisted page at https://nfh2025.rdgnbl.com/dashboard/ for the NFH team: one-click links to every Copysheet, Media folder and front-page doc, how complete each project is, visits per project and PDF downloads, sync health (edits that were skipped), recent changes, the daily broken-link check, and where visitors come from. Nothing links to it and search engines are told to skip it; anyone with the URL can open it.

- Built by `scripts/dashboard/build-dashboard.js` from `scripts/dashboard/dashboard.html` (`npm run dashboard`). The Publish workflow rebuilds it on every run, so numbers are at most about 15 minutes old.
- Visits are counted with GoatCounter (nonfictionhotlist.goatcounter.com) on the website only. The site counts each page and project once per visit, and PDF downloads as an event. The smoke test stubs GoatCounter, so test runs never count.
- To show the numbers, the workflow needs a GoatCounter API key with read access in the repo secret `GOATCOUNTER_TOKEN`. Without it, the dashboard says how to connect it.
- The link check (`npm run links`) runs daily and writes `content/link-check.json`. Social media sites block automated visits, so their links are listed as unchecked, not broken.
- Drive IDs the dashboard links to live in `content/drive.json`. If the kit is rebuilt, update them.
- `DASHBOARD_SAMPLE=1 npm run dashboard` fills in sample numbers for design previews. Never publish that.

## News, laurels and status

These are edited in each project's sheet (Status on the Page tab, plus the Laurels and awards and News tabs). A news item needs a source link to appear. Laurels show under the logline on a project page, the first one appears on the project's card, and the newest news item shows as "Latest" above the tabs. `research/` keeps the October 2026 research trail that seeded them.

## Images

Originals are not in the repo. They live in the shared folder `NFH 2025 SELECTED PROJECT ASSETS`, one subfolder per filmmaker. To redo the processed images:

```sh
ASSETS_DIR="/path/to/NFH 2025 SELECTED PROJECT ASSETS" npm run images
npm run release
```

Which source file becomes each project's card, banner and stills is set in `scripts/images/process.py` (the original 19) and `scripts/images/process_late.py` (images added later). Framing is adjustable per project: `HERO_FY` moves a banner crop up or down, and `FOCUS_X` / `FOCUS_Y` set where narrower views of the banner are anchored. Flat white or black bars at the edges of a source image are trimmed automatically.

## Deploying

`.github/workflows/publish.yml` runs on every push to `main`, every 15 minutes, and on demand. It pulls text from the Drive kit, builds the site and PDF, runs the smoke test, then publishes `site/` to the `gh-pages` branch. GitHub Pages serves that branch at nfh2025.rdgnbl.com. Scheduled runs with no Drive changes stop after the pull. GitHub pauses scheduled workflows in a repo with no activity for 60 days; re-enable it from the Actions tab if that happens.

One-time setup (already done if the site is live):

1. **GitHub Pages:** repo Settings → Pages → Source: *Deploy from a branch*, branch `gh-pages`, folder `/ (root)`. The custom domain fills in from `site/CNAME`. Tick *Enforce HTTPS* once the certificate is issued (usually within an hour).
2. **DNS** for rdgnbl.com: add a `CNAME` record, name `nfh2025`, value `matthewsmaglik.github.io`. If the DNS host is Cloudflare, set it to *DNS only* (grey cloud) so GitHub can issue the certificate.

## Troubleshooting

- `npm run check -- https://nfh2025.rdgnbl.com` runs the smoke test against the live site.
- **Site shows a GitHub 404:** Pages isn't pointed at `gh-pages`, or the deploy workflow hasn't run yet. Check the Actions tab.
- **"Domain does not resolve" in Pages settings:** the DNS record is missing or still propagating.
- **Certificate errors:** wait for GitHub to issue the certificate, then enable *Enforce HTTPS*. On Cloudflare, make sure the record isn't proxied.
- **Deploy fails at "must be built from src/page.html":** run `npm run build` and commit `site/index.html`.
- **Old content after a deploy:** GitHub Pages caches for about 10 minutes.
